請依下列標準評分（每項 0-5 分，可給小數）：

1. transferability 可轉譯性：台達員工讀完能否具體聯想到「我的工作也能
   這樣用」？有明確工作流程描述給高分，純技術發表或願景宣示給低分。
2. specificity 具體性：有具名企業＋量化成效（省多少時間、錢、人力）
   給高分。匿名案例、無數字的 PR 稿給低分。
3. novelty 新穎性：新趨勢、新做法給高分。已被廣泛報導兩年以上的老案例
   給低分。
4. narrativity 故事性：有畫面、有轉折、有人味，寫出來會好看。

同時判斷：
- area_category：必須是 "廠區現場"、"後勤支援"、"業務前台" 三選一。
  廠區現場＝預測維護、瑕疵檢測、產線排程、數位孿生、工業機器人等
  產線/工廠實體現場的 AI 應用。
  後勤支援＝HR、財務、法務、IT、採購供應鏈、知識管理等企業內部支援
  職能的 AI 應用。
  業務前台＝行銷、業務銷售、客服等面對客戶／市場端的 AI 應用。
- is_ai_application：文章核心是否為「AI 的實際應用／導入／開發」。
  純融資新聞、純模型發布、純評測跑分為 false。這只是輔助訊號，不是
  篩選門檻，即使判斷為 false 也要照常完整評分，不要因此省略欄位。
- hashtags：2-5 個開放式標籤，描述這篇文章的技術／應用主題，用你覺得
  最貼切的詞，不限詞庫（例如 "#預測性維護" "#客服自動化" "#RAG"
  "#數位分身"）。這些標籤會被拿去統計整個文章池裡的出現頻率，藉此
  偵測「最近很多文章都在談的主題」，請盡量用清楚、可能被重複使用的
  詞彙，不要每次都造新詞。
- one_line_summary：用一句話（30字內）說明這篇在講什麼。
- key_facts：列出文中最重要的 2-4 個可引用事實（含數字），之後生成
  文章時只允許使用這些事實。每個事實附上原文中的對應句子。

輸出 JSON schema：
{
  "is_ai_application": bool,
  "area_category": "廠區現場" | "後勤支援" | "業務前台",
  "hashtags": [str],
  "scores": {
    "transferability": float,
    "specificity": float,
    "novelty": float,
    "narrativity": float
  },
  "one_line_summary": str,
  "key_facts": [
    {"fact": str, "source_sentence": str}
  ]
}
